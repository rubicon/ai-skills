## [0.1.0] — 2026-10-18

### Added

- Organize and clean up GitHub stars with `gh` and `jq`, as a tool to run again whenever (or on a schedule): a read-only export, a proposed plan of List changes, assignments and unstars with a reason for each, a logged apply, and an undo.
- Interactive throughout: Claude runs every script, and the user decides in pop-up questions. Category changes (including List deletions), assignments and unstars each get "Approve all", "Review individually" (checkbox lists, 16 items per pop-up) or "Reject all"; the dry run ends in "Apply now", "Show every call first" or "Cancel"; a failed apply offers retry, undo or leave; undo picks a run, then asks once more. The user never runs a command or has to open a file.
- `plan.sh items` builds the pop-up items, `plan.sh drop` removes rejected ones along with what depends on them (a rejected merge keeps its source List, a rejected new List drops the moves into it), and `plan.sh allow-public` records the user's yes for repos that would become publicly categorized.
- `export.sh` records `starred_at` (star media type) and each star's List membership; later exports mark stars added since the last fully applied plan, so unfinished cleanup comes up again. The export's time is taken before reading, so a star added mid-export is proposed next time.
- `rules.md` in `~/.star-chart` (or `STAR_CHART_DIR`) holds the stale cutoff, the protection window, archived and deprecated-wording flags, a target List count, keep-always patterns, and categories to use or avoid.
- List consolidation toward a tight set of categories: `classify.sh` reports each List's size, flagged members, languages and overlap; plans can rename, merge and delete Lists. Merges and assignments become one membership call per repo, and a repo keeps its existing Lists, because `updateUserListsForItem` replaces the whole set (verified against GitHub's GraphQL schema).
- An enforced category approval: `plan.sh approve-categories` records the approved List changes and the id of every List they name, and the dry run, apply and List deletion refuse any change that differs, or a List that was replaced by another of the same name since.
- Private categorization is never published quietly: a change that puts a private List's repos into a public List is asked about separately and needs `--publishes-private` or `allow-public`. The approval records exactly which ones the user acknowledged, and the dry run and apply refuse any other, such as a List that turned private after the approval. Apply checks it again before every attempt, against the repo's Lists at that moment: a repo that is only in private Lists then goes into a public List only as the approval acknowledged.
- `dry-run.sh` lists every call with counts, a time estimate and an approval hash over the plan, the exact calls, and every List as the approval saw it. `apply.sh` makes exactly those calls and holds each one to that approval: Lists are identified by id (never looked up by name, so a List that took an approved name is never written to), every List a call names must keep the name and visibility the dry run showed, and a membership change applies only the approved change to the repo's Lists as they are right before the call, so edits made on another device meanwhile are kept. Each call carries a contract: a List a repo ends up in must be in its final approved state (after the plan's renames; a created List as approved), a List it leaves must be as approved or gone, and a rename's List must have the approved name, description and visibility. One check (`jq/contract.jq`) holds apply and undo to their contracts, against a fresh read before the first call (nothing changes if your Lists moved since the dry run) and again before every attempt of every call, retries after a rate limit or server error included; a call that no longer holds is refused. Success needs a complete answer; after a server error or an answer cut off, the re-read shows whether the call landed (for an unstar or a re-star, whether the repo is still starred), so it is neither repeated nor lost. Protection is re-read before every unstar. `scripts/tests/write-paths.md` lists every write path against these rules with the test for each, and the suite fails if any named test is missing.
- Resumable and recoverable: each change is logged before it is sent and again with its outcome (`ok`, `failed`, `unknown`, `refused`, `exists`; a call that got no answer or a server error stays `unknown` even if a retry is then refused); anything other than `ok` or `exists` leaves the plan unfinished (exit 2, the baseline stays); a safety check that cannot be completed, or gives no clear answer, refuses the call; re-running apply skips finished calls, and refuses (rather than takes over) a same-name List an interrupted run may have created; `delete-lists.sh --run` deletes only approved Lists that are empty and are the same List (by id) the export named, never one that has taken an approved name since, rechecking each one right before deleting it; `undo.sh --list-runs` and `undo.sh --run` reverse a run the same way (re-star, reverse each membership change while keeping later edits, rename back, recreate deleted Lists with their visibility), reversing each call from its last attempt only, resumable after a failed step, following a List through every recreation, and refusing a step whose List changed since the run, checked against the List state apply logged at each call.
- Runs on the Bash 3.2 that ships with macOS; the test suite drives `apply.sh` end to end against a stand-in `gh` (`scripts/tests/bin/gh`) and runs in CI on Ubuntu and macOS.
- Rate-limit backoff and a 300 ms throttle; detects a token without the `user` scope, and a `GH_TOKEN` that overrides the stored login, and prints commands that work either way; new Lists are created last in case GitHub limits how many a user can have.
